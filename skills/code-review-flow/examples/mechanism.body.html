取消任务，不等于阻止结果发布

理解取消为何没有闭环：计算状态和发布许可是两件事。

“已经点了取消”并不能证明“以后不会发布”。本例 worker 启动时只读取一次状态，之后仍可能把结果发布出去。决定边界在发布时，而不仅在开始时。

示例审查结论：修复发布缺口后再合入

计算状态

worker 是否还在工作。停止计算可以节省资源，但不自动撤销已进入发布阶段的结果。

发布许可

结果现在能否对外可见。本例要求：取消确认之后，不得发生新的发布。

需要改变的是发布边界

场景要求本例已知实现
正常完成允许发布发布结果
发布前取消已确认不再发布缺少发布时约束
取消前已经发布本材料未定义不推断自动撤回

修复方向：以原子条件控制发布。简单地在发布前读取一次状态，仍可能留下读取与发布之间的竞争窗口。

示例证据与边界

E1：取消确认之后不得新发布。E2：worker 启动时读取一次。E3：发布不校验取消状态。E4：虚构复现记录为“取消后仍发布”。

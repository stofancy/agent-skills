# 角色契约

将角色理解为可按需分配的职责，而不是每个 mission 固定存在的代理。一个独立 worker 可在风险允许时承担多个不冲突的角色；只在独立性构成正确性边界时才分开。每个 ticket 只能有一个 owner；Lead 始终对结果负责。

只有 Lead 可以创建、续接、替换或停止 worker。以下所有非 Lead 角色都不得派生子代理、转委派 ticket 或扩大自己的范围。

## 通用 ticket 输入

任何角色接手前都必须收到：mission/ticket ID、目标和非目标、基线 SHA 或等价基线、范围/禁止范围、可访问工作目录、依赖、验收项、时限、权限模式及要求的回报格式。只提供解决问题所需的最小代码摘录和上下文。

## Lead

- **输入：** 用户目标、代码库事实、账本、成员证据和风险。
- **行动：** 定义完成条件；接触代码；维护任务图；选择角色/路由；裁决取舍；协调依赖；处理异常；接受或拒绝交付。
- **输出：** mission brief、tickets、状态更新、接受决定与面向用户的真实结果。
- **限制：** 可救火写代码，但不得单独批准自己写的交付；不得把常规审查/验证回收为 Lead 自证；不得超出 mission 已公布的 fan-out 预算。

## Scout / Researcher

- **输入：** 待澄清的问题、搜索范围、相关目录或资料。
- **行动：** 只读勘探代码、配置、文档或外部资料；比较方案；指出不确定性。
- **输出：** 结论、依据（文件/命令/来源）、受影响边界、风险、待决问题和建议下一步。
- **限制：** 默认只读；不替 Lead 做产品/架构最终决定。

## Builder

- **输入：** 具备边界、依赖、验收项和写权限的 ticket。
- **行动：** 仅在分配的 worktree/分支/逻辑边界内实现，补充相关测试，记录命令和结果。
- **输出：** 基线/目标 SHA、diff/受影响文件、实现说明、已运行测试、未验证项与交接说明。
- **限制：** 一 worktree/逻辑边界一 writer；不合并他人变更；不自我批准；默认不推送/部署。

## Reviewer

- **输入：** 冻结 diff、目标 SHA、原任务约束与 Builder 交接。
- **行动：** 只读检查正确性、回归、安全、并发、接口、可维护性和测试空洞。
- **输出：** 按严重度排序的发现（位置、理由、可复现路径、建议）；无发现时明确说明审查范围。
- **限制：** 不以泛泛建议替代发现；不修改交付；高风险变更尽量与 Builder 使用独立模型或独立上下文。

## Verifier

- **输入：** 冻结 SHA、验收项、运行前提和可靠测试命令。
- **行动：** 在干净或等价环境运行构建、测试、迁移演练、行为验证或视觉验收。
- **输出：** 每条验收项的通过/失败/未验证、精确命令、退出码、环境前提、目标 SHA、原始产物索引。
- **限制：** 不把“命令能启动”当作行为通过；无法验证必须标为未验证；不要修改被验证交付。

## Integrator / Release

- **输入：** 已审查/验证的 tickets、集成顺序、目标分支和授权范围。
- **行动：** 处理合并次序、冲突和最终集成门禁；维护可追溯的集成结果。
- **输出：** 集成 SHA、合并/冲突情况、最终门禁状态和待处理项。
- **限制：** 只在 Lead/用户授权的分支写入；提交、推送、部署和不可逆迁移仍需单独授权；不得替代独立 Reviewer 与 Verifier。

## Advisor

- **输入：** 一个具体的决策、冲突或重复失败证据。
- **行动：** 提供独立诊断、备选路径与风险，而非接管工作区。
- **输出：** 推荐、反证、置信度与需要进一步验证的事实。
- **限制：** 一次性、只读、事件触发；不常驻旁听、不变成隐形 supervisor。

## UI Designer

- **输入：** 冻结的 UI brief、目标页面/流程和状态范围、设计系统/组件约束、运行入口、可访问性与响应式要求。
- **行动：** 定义信息层级、状态矩阵、交互与错误恢复路径、组件/视觉约束，并将取舍提交 Lead 裁决。
- **输出：** 可实现的设计约束、状态矩阵、可访问性验收点、关键 viewport/交互验收项与待决风险。
- **限制：** 仅 UI 任务启动；默认只读并将实现移交 Builder；不取代 Lead 的范围决定；不以单张静态图替代状态和交互说明。

## Visual QA

- **输入：** 冻结的 UI diff/SHA、UI brief、状态矩阵、运行入口、目标 viewport 和验收项。
- **行动：** 独立检查页面/流程在真实尺寸、关键状态与交互下的视觉、行为和可访问性。
- **输出：** 可定位到页面/viewport/state 的发现、复现步骤、截图或其他 artifact 索引、通过/失败/未验证结论。
- **限制：** 仅 UI 任务启动；不得与同一 Builder 自我验收；截图不是替代交互验证的唯一证据；不修改被验收交付。

## 统一回报格式

```text
身份：mission/ticket、角色、owner、harness、模型角色别名、状态
基线与范围：base SHA、head SHA、worktree/分支、受影响文件
工作：已做 / 未做 / 依赖变化
证据：命令、退出码、测试或产物索引
结论：发现或验收项、风险、阻塞、建议下一步
```

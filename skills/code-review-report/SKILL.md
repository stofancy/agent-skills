# PR 审查报告

目标：让 reviewer 理解改动想解决什么、实际怎样工作、什么场景仍有缺口，并据此判断下一步。复用固定渲染器，模型只组织内容和判断。

## 输入与边界

复用已有需求来源、冻结的 PR base/head、改动解释、findings 和验证记录。缺失影响结论的证据时注明缺口，交由审查工作补齐；排版不能把疑问升级为确定缺陷，也不需要为排版重新跑完整 review。

这是一项报告交付任务，可用于任意项目，单独使用或作为已有代码审查流程的输出阶段。遵循用户指定的阅读顺序；用于理解代码的报告可以先解释需求和实现，再展开缺陷。保留审查的严重度、触发场景和证据边界。

## 内容组织

1. 首段给出改动的核心模型和简短判断。用业务概念解释必要术语，不以文件清单开场。
2. 交代需求与旧行为，再解释 PR 如何改变它。跨仓库改动说明各方职责和信息流向。
3. 用代表场景串起「期望 → 实现 → 差距 → 影响」。数值示例写明单位、前提和来源；示意数据标为示意，不冒充生产观测。
4. 缺陷解释放在对应场景附近，附修复方向及可追查证据。只有因果链成立才合并根因，不为一条漂亮主线强行归并独立问题。
5. 末尾收束为合入判断、必要修复、待产品决定和验证边界。按实际情况取舍，不强制凑齐栏目。

章节数量由内容决定。正文保留决定结论的信息；文件路径、详细日志和证据链接可折叠。PNG 中折叠内容不可点击，因此触发条件、影响、严重度与未确认事项必须出现在正文。

## 图与排版

- 先用文字说明图要解释的关系，再画图。分支、职责边界、前后差异适合图；简单事实用文字或表格。
- 内置 `branch` 图表示一个起点、分支和汇合。不要把串行步骤画成并列分支；不适合此图的内容用段落或对照表，不为凑图扭曲语义。
- 避免横向长链、大封面、仪表盘、装饰性卡片和重复摘要。保留帮助理解的图，不追求图的数量。
- 默认桌面宽度 1100px、单栏阅读。无需手机适配、手机截图或 PDF；只有用户另有要求才扩展。
- 报告过长先删重复和非决策细节，不用缩小字号挤进图片。

## 生成

首次填充时读 [输入契约与示例](references/report-input.md)。以一个 JSON 为内容真源；使用固定脚本生成 HTML，不直接编辑生成文件。文本字段是纯文本，不支持 Markdown 或 HTML 标签。

以下命令可从任意工作目录执行。`SKILL_DIR` 指本 SKILL.md 所在目录，由当前 harness 实际加载位置确定；输入和输出路径由任务指定。脚本只读取输入、写入指定输出，不改源码或发送消息。输出目录需已存在，输出文件会覆盖。

```bash
node "$SKILL_DIR/scripts/render-review.mjs" "$REPORT_JSON" "$REPORT_HTML"
node "$SKILL_DIR/scripts/capture-report.mjs" "$REPORT_HTML" "$REPORT_PNG"
```

- HTML：Node.js 18+，零 npm 依赖、零模型调用、无外部资源。
- PNG：Node.js 与 Playwright，以及本机可用的 Chromium。截图脚本从当前工作目录解析 `playwright`；已有运行时可通过 `PLAYWRIGHT_MODULE` 指向其模块入口。`CHROME_PATH` 可指定浏览器，否则使用 Playwright 自带浏览器。缺依赖时报告实际缺项，优先使用当前 harness 已有浏览器截图能力，不静默安装软件。
- 截图脚本固定桌面宽度、等待字体、检查横向溢出并生成全页 PNG。浏览器/字体影响像素结果；相同 JSON 的 HTML 输出应确定。

## 检查与交付

渲染一次后查看桌面 PNG：文字是否可读、图的分支是否真实、表格是否截断、证据折叠后是否仍能理解结论。只修发现的问题，不进行多轮设计方向探索。

交付 JSON、HTML 和用户要求的 PNG，说明内容依据的审查快照及未完成范围。发送到聊天群或发布 PR 评论时使用目标平台已有工具与授权，本脚本不内置平台、收件人、账号或发布动作。

## 跨 harness 与成本

本目录是完整可搬迁的 Skill 包；正文和脚本不依赖某个模型、工具 API、绝对安装目录或会话状态。用户级共享真源为 `~/.agents/skills/code-review-report/`，与项目目录无关。支持该发现目录的 harness 直接读取；其他 harness 在其技能目录建立指向真源的链接，避免维护副本。所有资源路径相对于本 SKILL.md 解析。

已有审查结果可由主 reviewer 直接生成 JSON。需要委派编排时，沿用用户指定的低成本模型（如 Luna），一次传递完整证据与表达要求；编排者不重新判定业务结论。渲染和截图不调用模型，不强制委派或多模型复审。
